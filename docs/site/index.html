How it works

A zero-knowledge core anchored by append-only transparency structures.

01

Client encryption

All notes are sealed on your device with XChaCha20-Poly1305 and hybrid post-quantum signatures before transmission. The server never sees a key.

02

Committed ordering

The untrusted server sequences mutations in an RFC 9162 append-only Merkle tree and issues signed receipts with cryptographic merge deadlines.

03

Witness verification

Independent external witnesses cosign epoch checkpoints. Any attempt to modify, drop, reorder, or fork history is cryptographically caught.

Honest limits

We publish our explicit non-claims so trust is founded on boundaries, not marketing.

Hostile endpoint

Malware or keyloggers on your personal machine defeat all encryption guarantees.

Denial of service

An untrusted server can refuse service or withhold data. This is detected, not prevented.

Network traffic analysis

Your IP address and synchronization cadence remain visible to network observers.

Recovery key loss

If you lose your 24-word Recovery Key, your notes cannot be restored by anyone.
