# ADR-0003: In-Tree RFC 9162 Merkle Tree Implementation (`tn-merkle`)

- **Status**: Accepted
- **Date**: 2026-10-31
- **Deciders**: Bhavya (AlterBlock), AI Staff Engineer

---

## Context

TrustNotes requires append-only Merkle trees for three distinct data structures:
1. **Per-account operation tree**: Sequences ops within an account.
2. **Epoch tree**: Batches all accounts updated within an epoch.
3. **Global transparency log**: Logs epoch roots and releases, exposing static tile endpoints compatible with C2SP `tlog-tiles`.

We evaluated:
- **Option 1**: Adopting an existing third-party crate. Most existing Rust Merkle crates either implement generic binary trees with non-RFC domain prefixes, lack incremental consistency proof generation, or pull in C dependencies. The Go `transparency-dev` codebase is authoritative but cannot be embedded directly in a `#![forbid(unsafe_code)]` Rust core.
- **Option 2**: Implementing an in-tree, purpose-built RFC 9162 Merkle engine in `tn-merkle`.

---

## Decision

We implement a dedicated, pure-Rust RFC 9162 Merkle tree in `tn-merkle`.

### Key Technical Properties
1. **Strict RFC 9162 §2.1 Domain Separation**:
   - Leaf hash: $\text{MTH}(\{d\}) = \text{SHA-256}(0\text{x}00 \mathbin{\Vert} d)$
   - Interior node hash: $\text{MTH}(D) = \text{SHA-256}(0\text{x}01 \mathbin{\Vert} \text{MTH}(D[0..k]) \mathbin{\Vert} \text{MTH}(D[k..n]))$ where $k = 2^{\lfloor \log_2(n-1) \rfloor}$.
2. **Standard Proof Generation**:
   - Inclusion proofs: $O(\log n)$ sibling hashes.
   - Consistency proofs: $O(\log n)$ sub-tree boundary hashes proving tree $A$ is a prefix of tree $B$.
3. **Tile Storage**: Direct support for $2^8 = 256$-entry tile storage (`tlog-tiles`), matching C2SP specification for CDN caching.
4. **Differential Testing**: Implementation will be differentially tested against test vectors generated by Google's Go `transparency-dev` and RFC 9162 official test vectors.

---

## Consequences

- Full ownership of safety and error semantics: no foreign unsafe code, no panic paths on malformed inputs.
- Verification failures map directly to typed errors (`TnError::RootMismatch`, `TnError::HistoryGap`).
- Slight increase in code maintenance; mitigated by comprehensive property tests (`proptest`) and fuzz targets (`cargo-fuzz`).
